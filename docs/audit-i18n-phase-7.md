## 3. Font preload — unicode-range optimization

The IBM Plex Sans Arabic font (~133 KB) is heavy and only useful on Arabic pages. The Phase 7 sub-1 implementation uses a conditional preload in `BaseLayout.astro`:

```astro
<link rel="preload" href="..." as="font" type="font/woff2" crossorigin />
{locale === 'ar' && (
  <link rel="preload" href=".../ibm-plex-sans-arabic-arabic-400-normal.woff2" ... />
)}
```

| Audit | Expected | Actual |
|---|---:|---:|
| FR pages preloading Arabic font | 0 | **0** ✅ |
| EN pages preloading Arabic font | 0 | **0** ✅ |
| AR pages preloading Arabic font | 29 | **29** ✅ |

Combined with `unicode-range` in the `@font-face` declarations (which prevents the browser from downloading the Arabic font on FR/EN pages even if preload were broken), this saves approximately **133 KB per page load** for FR/EN readers — about 55% of the total font payload.

### Bug caught and fixed during audit

The first audit pass detected **10 broken links** in `dist/en/podcasts/index.html`. The "complete series in recommended order" list was using `getLocalizedUrl(...slug, locale)` with `locale='en'`, generating `/en/podcasts/{slug}/` URLs — but episode pages only exist as `/fr/podcasts/{slug}/` (the dynamic `[slug].astro` route is FR-only since episodes are produced in French first).

**Fix** : changed to `getLocalizedUrl(..., 'fr')` to point EN visitors to the FR episode pages directly (consistent with `PodcastCard.astro` which was already hard-coded to `'fr'`).
